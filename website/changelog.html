Changelog

What's new, version by version.

Kan's version number is bumped on every change to its public interface — the canonical value lives in VERSION. This page says what each bump changed, newest first.

v0.6.0

2026-08-09 · 14:59 IDT latest breaking

One namespace, and it's enforced.

  • Duplicate top-level names are now a hard error. Kan has a single flat namespace — every def, data type, and constructor shares it. Declaring the same name twice anywhere in a program (a file or anything it imports) used to silently shadow, which hid real bugs — e.g. a constructor and an accessor sharing a name, where the constructor quietly won and the accessor became dead code. The checker now rejects it with a clear message naming the clash.
  • Renamed eqInt/ltInt → eqInteger/ltInteger in std/integer.kan (the primitive-Integer comparisons), so they no longer collide with std/int.kan's eqInt on the inductive Int. If you compared primitive Integers, use the new names.

v0.5.0

2026-08-09 · 13:43 IDT breaking

Small categories, named honestly.

  • Renamed the category record Category → SmallCategory (breaking). Its objects live in universe U, so it houses exactly the small categories — finite categories, posets, a monoid as a one-object category, the terminal category One, the opposite category op, products. The accessors, Functor, NatTrans, and the Kan-extension statements all follow the new name. If you referenced Category, rename to SmallCategory.
  • Charted the path to large categories (Grp, Set, Top). They don't fit SmallCategory on two counts — objects would need a higher universe, and morphism equality would need function extensionality. The fix is a universe-polymorphic, setoid-based Category (hom-equality by an explicit equivalence rather than Id), sketched in open-questions §4. It's additive to the type theory — no soundness risk — and gated only on universe polymorphism.
  • Worked example: the category of Groups. Objects (groups), morphisms (group homomorphisms), identity, and composition — built and type-checked, with (ℤ, +) as a concrete object reusing the proven commutative-ring axioms from std/int.kan.

v0.4.1

2026-08-09 · 12:53 IDT

A math library on the reals.

  • A small, robust math library on the constructive reals. sqrtQ (√ by Newton's method, correct for all inputs — the iteration count is derived from the argument's size), expQ (exp with argument reduction so it converges for any input), and powNatC (natural-number powers by binary exponentiation). All computed and cross-checked by three backends.
  • "New version available" badge. Returning visitors to the home page see when Kan has changed since their last visit (via localStorage; nothing is sent anywhere).

v0.4.0

2026-08-09 · 12:31 IDT first versioned

Versioned; exact reals showcased.

  • Versioning begins. Established the VERSION file as the single source of truth and added the prominent version + date display to the site — bumped on any public-interface change.
  • Exact-reals showcase page added to the website.
  • The language as it stood at this baseline: a verified integer tower (ℤ proved a commutative ring, axiom-free), type-enforced rationals with divide-by-zero a type error, constructive reals (√2, π, e to any precision), and lawful category theory + Kan extensions.
